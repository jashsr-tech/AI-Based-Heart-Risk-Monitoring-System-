5. STANDARD SCALER FITTING ON IMPUTED TRAIN_DEV NUMERICAL FEATURES
--------------------------------------------------------------------------------
   MATHEMATICAL SPECIFICATION:
   sklearn.preprocessing.StandardScaler computes POPULATION variance (ddof=0, denominator N):
     mu_j    = (1 / N) * sum_{i=1}^N X_{i,j}
     sigma_j = sqrt( (1 / N) * sum_{i=1}^N (X_{i,j} - mu_j)^2 )
     Z_{i,j} = (X_{i,j} - mu_j) / sigma_j

   DISTINCTION BETWEEN POPULATION (ddof=0) AND SAMPLE (ddof=1) STANDARD DEVIATION:
     - HRV calculation in Stages 3-4 uses SAMPLE standard deviation (ddof=1, denominator M - 1, Bessel's correction)
       because K=10 is a small local sample of heartbeats.
     - StandardScaler uses POPULATION standard deviation (ddof=0, denominator N) across the complete training partition.
       At N = 66,679, sqrt(N / (N - 1)) = sqrt(66679 / 66678) = 1.0000075 (a relative difference of 0.00075%).
     - We use sklearn's standard population variance implementation without manual modification.

7. SCALER PURPOSE & ARCHITECTURAL DOCUMENTATION
--------------------------------------------------------------------------------
   * Random Forest Scale-Invariance:
     Decision tree ensembles (Random Forest, Extra Trees, Gradient Boosting) rely strictly on
     rank-order thresholds (e.g. x_j <= threshold). They are mathematically invariant to monotonic
     affine transformations such as z = (x - mu) / sigma.
   * Why StandardScaler is Preserved in the Production Pipeline:
     1. Algorithmic Comparability: Enables benchmark comparisons against scale-sensitive models
        (Logistic Regression, Support Vector Machines, Neural Networks).
     2. Production Modularity: Encapsulates all preprocessing into a clean, reusable Scikit-Learn
        Pipeline object that guarantees identical input shapes across training and deployment.
     3. Numerical Stability: Prevents large amplitude features (e.g. R-peak at 3.5 mV) from
        causing floating-point precision differences when comparing multi-lead visualizations.
